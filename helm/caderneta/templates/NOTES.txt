Caderneta {{ .Chart.AppVersion }} installed as "{{ .Release.Name }}".

1. Follow the boot:

   kubectl logs -f -n {{ .Release.Namespace }} \
     -l app.kubernetes.io/instance={{ .Release.Name }}

   The container runs `alembic upgrade head` before starting the bot.

{{- if not .Values.telegram.ownerChatId }}

2. WARNING - OWNER_CHAT_ID is empty: the bot is in bootstrap mode and does NOT
   process commands. Send it any message, take the chat_id from the reply (it is
   in the log too) and reinstall with:

     helm upgrade {{ .Release.Name }} ./helm/caderneta \
       --reuse-values --set telegram.ownerChatId=<your_id>
{{- else }}

2. Access granted only to chat_id {{ .Values.telegram.ownerChatId }}.
{{- end }}

{{- if not .Values.telegram.existingSecret }}

3. SECURITY WARNING: the token was stored in a Secret created by the chart, so
   it lives in the release history. For production, create the Secret outside:

     kubectl create secret generic caderneta-token \
       --from-literal=BOT_TOKEN=<token> -n {{ .Release.Namespace }}
     helm upgrade {{ .Release.Name }} ./helm/caderneta \
       --reuse-values --set telegram.existingSecret=caderneta-token \
       --set telegram.botToken=""
{{- end }}

{{- if .Values.persistence.enabled }}

4. Database backup (the PVC has resource-policy: keep, so it survives a
   `helm uninstall`):

     kubectl exec -n {{ .Release.Namespace }} \
       deploy/{{ include "caderneta.fullname" . }} -- \
       sqlite3 {{ .Values.config.dbPath }} ".backup /tmp/bkp.db"
     kubectl cp {{ .Release.Namespace }}/$(kubectl get pod -n {{ .Release.Namespace }} \
       -l app.kubernetes.io/instance={{ .Release.Name }} \
       -o jsonpath='{.items[0].metadata.name}'):/tmp/bkp.db ./caderneta-backup.db
{{- else }}

4. WARNING: persistence.enabled=false - entries vanish on every restart.
{{- end }}

Health: GET /healthz (liveness) and /readyz (readiness) on port {{ .Values.config.healthPort }}.
